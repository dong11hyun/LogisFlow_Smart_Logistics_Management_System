## 2단계 상세설명

#### 2-1 비정규화 스키마 설계
- 이미 1-2 에서 완료. 비정규화 스키마 구현.
`01_schema.sql`
```sql
CREATE TABLE shipments (
    -- 기존 컬럼들
    shipment_id SERIAL PRIMARY KEY,
    company_id INT,
    origin_warehouse_id INT,
    destination_warehouse_id INT,
    created_at TIMESTAMP,
    
    -- ⬇️ 비정규화 컬럼 (새로 추가) ⬇
    current_status VARCHAR(50),            -- 현재 상태
    last_updated_at TIMESTAMP,             -- 마지막 업데이트 시간
    origin_warehouse_name VARCHAR(100),    -- 출발 창고명
    destination_warehouse_name VARCHAR(100) -- 도착 창고명
);
```

#### 2-2 파티션 테이블 구성 (`02_partitioned_schema.sql`)
```powershell
# 파티션 스키마 적용
docker exec -it logisflow-postgres psql -U postgres -d logisflow -f /docker-entrypoint-initdb.d/04_partitioned_schema.sql

# 적용 확인
# 파티션 목록 확인
docker exec -it logisflow-postgres psql -U postgres -d logisflow -c "SELECT relname FROM pg_class WHERE relname LIKE 'shipment_updates%' ORDER BY relname LIMIT 10;"
```

- 일반테이블 (기존)
```
shipment_updates (하나의 거대한 테이블)
┌─────────────────────────────────────────────────────────┐
│  500억 건 데이터가 한 곳에!                              │
│  ├── 2020년 1월 데이터                                  │
│  ├── 2020년 2월 데이터                                  │
│  ├── ...                                                │
│  └── 2026년 1월 데이터                                  │
│                                                          │
│  조회: "2026년 1월 데이터 찾아줘"                         │
│  → 500억 건 전체를 스캔해야 함 (느림!)                   │
└─────────────────────────────────────────────────────────┘
```

- 파티션 테이블 (새로 만든 것)
```
shipment_updates (부모 - 논리적 테이블)
├── shipment_updates_2024_01 ──┬── 물리적으로 분리된 파일
├── shipment_updates_2024_02   │
├── ...                        │
├── shipment_updates_2025_12   │
└── shipment_updates_2026_01 ──┘  ← "2026년 1월 찾아줘" 
                                    → 이 파티션만 스캔! (빠름!)
```

- 실제 동작 예시
```sql
-- 2026년 1월 10일 데이터 INSERT
INSERT INTO shipment_updates (shipment_id, status_code, timestamp)
VALUES (1, 'DELIVERED', '2026-01-10 12:00:00');
PostgreSQL이 자동으로 timestamp를 보고 shipment_updates_2026_01 파티션에 넣어요!

-- 2026년 1월 데이터만 조회
SELECT * FROM shipment_updates 
WHERE timestamp >= '2026-01-01' AND timestamp < '2026-02-01';
```
>PostgreSQL이 자동으로 shipment_updates_2026_01 파티션만 스캔! (Partition Pruning)
